## P1 — 发布后短期优化（上线后 1-2 周内）

### P1-1 后端启动断言

`app/database.py` 当前在 `DATABASE_URL` 未设置时可降级为 SQLite。生产已经人工确认使用 PostgreSQL，但建议后续加入启动断言，防止误操作：

```python
assert DATABASE_URL.startswith("postgresql"), "DATABASE_URL must be PostgreSQL in production"
```

### P1-2 CORS Middleware

微信小程序本身不受浏览器 CORS 约束，不影响上线。后续可加 `CORSMiddleware` 方便 Web 模拟器或其他管理端调试。

### P1-3 alembic.ini SQLite URL 注释化

`alembic.ini` 中的 SQLite URL 在运行时已被 `alembic/env.py` 覆盖，但容易误导维护者，建议注释说明。

### P1-4 requirements.txt 版本锁定

部署稳定后执行：

```bash
pip freeze > requirements-lock.txt
```

后续服务器部署优先使用锁定版本，降低依赖漂移风险。

### P1-5 生产日志与错误排查

- uvicorn 日志和 systemd journal 定期检查。
- Hunyuan / TMT 诊断日志可用于排查例句生成问题。
- 配置日志轮转，防止磁盘占满。

### P1-6 服务器基础监控

- CPU / 内存 / 磁盘监控。
- 磁盘剩余空间告警。
- HTTP 健康检查告警。

### P1-7 后端错误告警

- systemd 崩溃后自动重启已配置。
- 可选：配置邮件或 webhook 告警。

### P1-8 API 限流

- 对 `/api/analyze-english` 添加限流，控制 Hunyuan 成本。
- 对写入接口添加基础限流。
- 限流触发返回 HTTP 429，前端友好提示。

### P1-9 用户反馈入口

关于页已有“联系开发者”入口，发布后需验证复制邮箱与反馈链路是否顺畅。
