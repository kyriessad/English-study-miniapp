# Phase 6C 收口文档：首页入口回归与删除链路修复

## 一、阶段背景

Phase 6C 目标是首页视觉与入口回归，重点不是新增复杂功能，而是让首页在不同卡片数量下有更清晰的入口和状态：

- 0 张卡时显示一键体验流；
- 有卡片后恢复正常首页卡片列表；
- 保留"添加卡片 / 进入复习页"主入口；
- 隐藏分析中、待重试、待同步、pending、failed 等技术状态；
- 保留学习状态标签和必要的"需补充理解"。

## 二、主要改动

### 1. 0 张卡一键体验流

- 首页 0 张卡时不显示筛选药丸；
- 不显示搜索框；
- 显示 3 个预设卡片：
  - Serendipity（单词）
  - Light in the cracks（短语）
  - Grow through what you go through.（句子）
- 点击预设卡片后直接创建卡片；
- 创建成功后 toast 显示"已保存"；
- 后端关闭但本地保存成功时，toast 显示"已保存"。

### 2. 有卡片时首页结构

- 显示首页主标题、学习统计、状态概览；
- 保留"添加卡片"和"进入复习页"两个主按钮；
- 按钮比例保持约 25% / 75%；
- 1 张以上显示筛选药丸；
- 超过 10 张显示搜索框；
- 卡片列表保留学习状态标签；
- 隐藏技术状态标签，避免把 pending / failed / 待同步等实现细节暴露给用户。

### 3. 删除链路修复

记录 Phase 6C 期间连续修复的三个删除相关问题：

**A. commit b3fd58 — 修复卡片删除 404 / pending 处理**

- 修复单卡删除 / 批量删除时，后端 404 导致整体失败的问题；
- pending/local-only 卡不发 DELETE，直接删除本地；
- DELETE 404 视为后端已无此卡，继续删除本地；
- 网络错误 / 5xx 不删除本地；
- 批量删除逐张独立处理，不因单张失败中断整体。

**B. commit 355b27 — 修复复习页旧 session 包含已删除卡片**

- 修复已删除卡仍出现在复习页的问题；
- 删除成功后清理本地 review/session 相关缓存；
- review 页加载 session 时防御性过滤已经不存在的 card_id；
- 如果旧 session 过滤后为空，会尝试 restart 获取新 session；
- 验证 Serendipity 创建后能进入复习页，且已删除 look at 不再出现。

**C. commit effc882 — 修复本地缓存清空后首页仍显示幽灵卡片**

- 修复后端关闭时删除本地预设卡后首页仍显示幽灵卡片的问题；
- 根因是 cardsCache 已为空，但 page.data.cards 没有同步清空；
- 修复后 loadLocalCache 在 localCards.length === 0 分支先 setData({ cards: [] })，再 applyFilters；
- 验证删除本地卡后首页刷新不再显示幽灵卡片，也不会再进入"未找到卡片"的详情页。

## 三、验收结果

以下验收均已通过：

- **A**：清空全部卡片后，首页进入 0 张卡状态，显示 3 个预设卡片；
- **B**：点击 Serendipity 后创建成功，首页出现 Serendipity；
- **C**：1 张卡时显示筛选药丸，不显示搜索框，卡片右上角显示学习状态，不显示技术状态；
- **D**：超过 10 张卡时显示搜索框，搜索 ser 能搜到 Serendipity，清空搜索后恢复列表；
- **E**：点击进入复习页能看到 Serendipity，不再出现已删除的 look at；
- **F**：删除 Serendipity 后再次进入复习页，只出现剩余卡片，例如 ChatGPT；
- **G**：后端关闭时点击预设卡片，toast 显示"已保存"，首页出现卡片，刷新后仍在；
- **H**：后端关闭时删除本地预设卡，toast 显示删除成功，首页刷新后不再出现；
- **I**：后端关闭时删除真实后端卡，提示删除失败，刷新后卡片仍保留；
- **J**：后端开启时删除真实后端卡，DELETE 200 后首页消失，刷新后不回来；
- **K**：project.private.config.json 已还原；
- **L**：最终 git status --short 干净。
